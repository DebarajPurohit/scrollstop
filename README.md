# Stop Doom Scroll --- Project Documentation

This directory is the source of truth for product, UX, technical,
security, testing, release, and project decisions.

## Maintenance rule

For every feature or change:

1.  Inspect relevant documents.
2.  Plan the change.
3.  Implement and test.
4.  Identify documentation impact.
5.  Update affected documents in the same change/PR.
6.  Record significant decisions in `PRODUCT_DECISIONS.md` or
    `TECHNICAL_DECISIONS.md`.
7.  Update `PROJECT_STATUS.md` and `RISKS.md` when status or risk
    changes.

Do not duplicate the same requirement across documents unless the second
location is a deliberate reference.
